# 猫课 CRM V1 PRD（最新版）

版本：V1.0
日期：2026-03-15
状态：可进入开发

## 1. 背景与目标

本版本目标是在 1-2 个月内上线一个可稳定运行的 CRM，优先满足销售与咨询师协作场景。

业务目标：
- 建立统一客户档案与负责人机制
- 建立客户服务流（跟进、服务、提醒、导入）
- 实现角色权限与操作审计，保证数据安全可追溯

## 2. V1 范围（MVP）

包含：
- 用户与权限（销售、咨询师、管理员、超级管理员）
- 客户管理（增删改查、状态、标签、负责人）
- 销售跟进记录
- 咨询师服务记录
- 服务提醒
- 课程购买记录导入（Excel/CSV）
- 上课记录导入（Excel/CSV）
- 客户时间线聚合展示
- 审计日志（关键动作）

不包含：
- Agent 自动分析、自动建议、自动报告（V2+）
- 向量数据库、事件总线、数据仓库（V2+/V3）

## 3. 角色与权限

角色定义：
- sales（销售）
- consultant（咨询师）
- admin（普通管理员）
- super_admin（超级管理员）

权限矩阵（摘要）：
- super_admin：管理所有用户，创建/删除管理员，查看全量数据
- admin：创建销售和咨询师，修改成员，删除客户，查看全量客户
- sales：创建客户、编辑自己负责客户、添加跟进、查看咨询记录与提醒
- consultant：查看客户脱敏信息、创建服务记录、创建提醒、上传咨询分析

数据访问规则：
- sales 默认仅可访问 `owner_user_id = 当前用户` 的客户
- admin/super_admin 可访问全部客户
- consultant 仅访问被分配服务关系的客户（V1 若无分配关系表，则按“可读全部脱敏客户”执行）

## 4. 核心业务流程

### 4.1 客户管理
- 创建客户：录入基础信息，自动设置负责人与初始状态
- 编辑客户：支持更新状态、行业、来源、标签、负责人
- 删除客户：仅管理员可操作，采用软删除

### 4.2 销售跟进
- 销售可为客户新增跟进记录
- 跟进支持记录沟通方式、内容、结果、下次行动时间
- 写入后自动更新客户 `last_followup_at`

### 4.3 咨询服务
- 咨询师可新增服务记录（时间、内容、反馈、满意度）
- 咨询师可上传咨询分析文件并写入摘要

### 4.4 服务提醒
- 咨询师/销售可创建提醒，支持执行人、优先级、截止时间
- 提醒状态：pending / done / canceled

### 4.5 数据导入
- 支持导入课程购买与上课记录
- 每次导入生成批次号，记录成功/失败条数
- 失败行保存错误原因，支持回溯

### 4.6 客户时间线
- 聚合展示跟进、服务记录、咨询分析、购买、上课、提醒事件

## 5. 数据与安全原则

- 核心业务数据仅允许用户操作或系统规则更新
- 所有删除行为采用软删除
- 关键操作写入 `audit_logs`（删客户、改负责人、改状态）
- 手机号/微信对咨询师默认脱敏展示（后端返回掩码值）

## 6. 非功能要求

- 可用性：工作日 9:00-21:00 可用率 >= 99.5%
- 性能：客户列表分页接口 P95 < 300ms（10万客户规模）
- 安全：JWT 鉴权、密码哈希、最小权限、操作审计
- 可维护性：模块化 API、统一错误码、可迁移数据库脚本

## 7. 里程碑

M1（第1-2周）：
- 用户/权限、客户管理基础 CRUD

M2（第3-4周）：
- 跟进、服务记录、提醒、时间线

M3（第5-6周）：
- 导入能力、审计日志、权限收口、上线准备

## 8. 验收标准（DoD）

- 四类角色权限生效且通过用例测试
- 客户、跟进、服务、提醒、导入功能可完整走通
- 导入失败可定位到具体行和错误原因
- 审计日志可查询关键操作记录
- 关键接口通过集成测试并满足性能指标
